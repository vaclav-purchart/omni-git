# Commit (message box + Commit / Amend) — implementation plan

Spec: `docs/superpowers/specs/2026-07-31-commit-design.md`
Branch: `m4-commit`

## Task 1 — backend `git::commit`

**Files:** new `src-tauri/src/git/commit.rs`, `src-tauri/src/git/mod.rs`,
`src-tauri/src/git/stage.rs`

- `pub fn commit_args(message: &str, amend: bool) -> Vec<&str>` — pure argv
  builder starting at `"commit"`. `["commit", "-m", message]`, with `"--amend"`
  inserted after `"commit"` when amending.
- `pub fn commit(app, repo_path, message, amend) -> Result<String, GitError>` —
  `run(commit_args(..))`, then `run(["rev-parse", "HEAD"])`, returning the
  trimmed SHA.
- `pub fn head_commit_message(app, repo_path) -> Result<Option<String>, GitError>`
  — `None` when `head_exists` is false, else `git log -1 --pretty=%B` trimmed of
  its trailing newline.
- Make `stage::head_exists` `pub(crate)` and reuse it.
- Register `pub mod commit;` in `git/mod.rs`.

**Tests** (`#[cfg(test)]` in `commit.rs`, same tempdir + shell-out style as
`stage.rs`, since these fns need an unavailable `AppHandle`):

- `commit_args_plain` / `commit_args_amend` — pure, assert exact argv.
- `commit_creates_commit_with_message` — stage a file, commit, assert
  `git log -1 --pretty=%B` matches and the commit count went 1 → 2.
- `amend_replaces_head_without_adding_commit` — commit, amend with a new
  message, assert count stayed at 1 and the message changed.
- `commit_preserves_multiline_message` — a message with a blank line and a body;
  assert subject and body both survive (guards the no-shell-escaping claim).
- `head_commit_message_none_on_unborn_branch` — assert `git log` fails on a
  fresh `init`, which is the condition `head_exists` gates on.

## Task 3 — `CommitBox` component

**Files:** new `src/detail/CommitBox.tsx`, `src/detail/CommitBox.css`

Props: `repoPath`, `stagedCount`, `canAmend`, `onCommitted(sha)`.

- Draft in `usePersistentState<string>(\`commit-draft:${repoPath}\`, "")` — see
  spec for why this cannot be plain `useState`.
- `amend` checkbox: on tick, stash the current draft in a ref, fetch
  `headCommitMessage`, put it in the box; on untick, restore the stashed draft.
  Disabled when `!canAmend`.
- Commit button disabled when `message.trim() === ""`, or
  `stagedCount === 0 && !amend`, or `busy`.
- `onKeyDown` on the textarea: `(e.metaKey || e.ctrlKey) && e.key === "Enter"`
  → submit.
- On success: clear draft, untick amend, `onCommitted(sha)`. On failure: inline
  dismissable error banner (reuse `.wc-action-error` markup/classes).

**Tests** (`src/detail/CommitBox.test.tsx`, mocking `../ipc/bindings` as the
existing detail tests do):

- disabled with an empty message
- disabled when nothing is staged and not amending
- enabled when amending with nothing staged
- clicking Commit calls `commands.commit(repoPath, message, false)` and then
  `onCommitted` with the returned sha
- Ctrl+Enter in the textarea commits
- amend tick prefills from `headCommitMessage`; untick restores the typed draft
- a failed commit shows the stderr and does **not** call `onCommitted`
- the draft is cleared from localStorage after a successful commit
